# 外卖大乱送 · Delivery Chaos — 设计文档 v0.1（MVP）

> 负责人：PM（规划/设计/验收）· 工程：Coder（实现）
> 目标：做出一个 **2–4 人联机、每局都会自然翻车出名场面** 的外卖小游戏。MVP 只验证一件事：**自己和朋友玩一局，笑不笑得出来。**

---

## 1. 设计支柱（所有取舍都按这个排序）

1. **意外要好笑，不要让人烦。** 翻车、洒汤、披萨飞出去——要"可见、可预期、可归因"：玩家看得到货在晃，知道是自己拐太急。不能是莫名其妙的随机惩罚。
2. **一眼就懂。** 不教规则：看到订单卡 → 去餐厅 → 去顾客家 → 停下来就交货。
3. **合作 > 竞争。** 全队共享一个小费池和星级目标；个人数据只用来做结算时的"颁奖"（洒汤王、翻车王）。
4. **小而完整。** 宁可 3 种食物都好玩，也不要 8 种食物都一般。

---

## 2. 核心循环

```
订单池出现订单 → 任一玩家骑到【餐厅】停下取餐（先到先得）
→ 骑到【顾客】停下交货 → 按"完整度 × 速度 × 特殊要求"算小费 → 全队小费累加
→ 4 分钟结束 → 结算星级 + 个人奖项 → 再来一局
```

- 每名玩家 **同时只能拿 1 单**。
- 取餐/交货：进入目标圈（半径 5 m）且 **速度 < 4 m/s 持续 0.5 s** 自动完成（无需按键），圈上有进度环。
- 一局 **240 秒**。

---

## 3. 地图（程序生成，seed 决定，所有客户端一致）

- 网格城市：**5 × 5 个街区**，街区边长 36 m，道路宽 12 m（格距 48 m），整图约 240 m 见方，外圈有围墙。
- 每个街区放 1–4 栋方块楼（高度 6–30 m，明快配色）；**1 个街区是公园**（草地，无楼，有几棵树/长椅，可穿行）。
- **3 家餐厅**（每家只出一种食物），明显的招牌颜色 + 头顶图标：
  - 王记汤馆（汤）· 红色
  - 披萨大叔（披萨）· 橙色
  - 冰冰甜品（冰淇淋）· 粉色
- **8 个顾客点**（楼前的门口标记，带门牌名，如"3号楼 张先生"）。
- **混乱道具**（全部是静态碰撞体）：
  - 4–6 个 **跳台**（倾斜方块，在路中间）——飞起来 → 落地冲击 → 冰淇淋球会掉
  - 8–12 条 **减速带**（路面上的矮条）——颠一下 → 汤晃
  - 若干路障/垃圾桶（可撞）
- 生成必须 **只依赖 seed**（自写的 mulberry32 RNG，放在 `shared/`），服务器下发 seed。

## 4. 摩托车（乐趣来源：一点点"不稳"）

**物理方案：Arcade "球形车"**。碰撞体是一个 cannon-es 球（r = 0.5 m）；航向 `heading`、车身倾斜 `lean` 是独立变量，由我们自己算；模型只是跟着球走的视觉。这样上坡、跳台、撞墙都稳定，手感完全可调。

| 参数 | 起始值 | 说明 |
|---|---|---|
| 最高速度 | 16 m/s | |
| 加速 | 9 m/s² | |
| 刹车 | 18 m/s² | |
| 倒车最高 | 4 m/s | |
| 转向角速度 | `steer × lerp(2.2, 1.2, v/vmax)` rad/s | 速度为 0 时不能原地转 |
| 侧向抓地 | 侧向速度衰减 8 /s；按住 Space（手刹）降到 2 /s → 甩尾 | |
| 重力 | 20 m/s² | 更有"分量感" |

控制方式：地面接触时直接设置水平速度趋向目标（arcade），垂直速度交给物理。

**倾斜/平衡模型（核心手感，务必做到可调）：**

```
lean'' = G·sin(lean) − K(v)·(lean − leanTarget) − C·lean' + 扰动
leanTarget = −steer · clamp(v/8, 0, 1) · 0.5 rad
K(v) = 4 + 26·clamp(v/6, 0, 1)      // 低速时不稳，高速有"陀螺"稳定性
G = 9, C = 6
扰动 = 低速噪声晃动(v<4 时幅度大) + 侧向加速度 + 颠簸(减速带/落地) + 撞击
```

- **"放脚"**：速度 < 1 m/s 且没按油门 → K = 40（停车时不会自己倒）。
- **翻车条件**：|lean| > 1.05 rad（60°），或撞墙法向速度 > 7 m/s（3–7 m/s 只给一个大扰动）。
- **翻车**：1.8 s 失控（车 + 人视觉翻滚、屏幕震动、"翻车啦！"大字），货物大损（见下），然后原地扶正（如果卡在楼里就挪到最近道路上）。
- **R 键**手动扶正（3 s 冷却）。
- 目标体感：乱开的玩家大约 **每分钟翻 1 次**；小心开的玩家可以几乎不翻。

## 5. 三种食物（混合物理："先假装，坏了再变真的"）

货物放在车后架上。**平时用简单的弹簧/摆模型模拟**（稳定、可调、可同步），**出事的那一刻生成真正的 cannon 刚体碎片**飞出去（披萨盒、冰淇淋球、汤滴），在地上留 8 s 后消失。输入都是 **车身局部坐标系下的加速度** `aLocal = (侧向, 垂直, 纵向)` 和 `lean`。

所有货物模型都写成 **纯函数/纯类，不依赖 three.js**（放在 `src/sim/cargo.ts`），方便单元测试和联机同步。

### 5.1 汤（会洒）· 完整度 = 剩余汤量
- 状态：液面晃动 `s = (sx, sz)`，二维阻尼弹簧：`s'' = −25·s − 2.5·s' − 0.06·aLocal.xz`（lean 也加进侧向分量）。
- `|s| > 0.5` 时溢出：`level −= (|s| − 0.5) × 0.8 × dt`，并喷汤滴粒子。
- 翻车：`level ×= 0.4`。
- 视觉：碗 + 会倾斜的液面圆盘，液面高度随 level 下降。

### 5.2 披萨塔（会倒）· 完整度 = 剩余盒数 / 初始盒数
- 订单决定叠几盒：2–5 盒（越多小费越高）。
- 状态：塔身倾斜 `t = (tx, tz)`，倒立摆：`t'' = −k·t − c·t' + g·t − aLocal.xz·drive·(n/3)`；n 越大越不稳。起始 k=18, c=3, g=6, drive=0.03。
- `|t| > 0.35` → 最上面一盒飞出去（生成刚体碎片，继承车速 + 甩出方向），`t` 回退到 0.1。
- 翻车：全部飞出。
- 视觉：扁盒子一层层叠，**每层按 t 做递增偏移和旋转**（看得到塔在晃——这是直播名场面的关键）。

### 5.3 冰淇淋（会融化）· 完整度 = 剩余球数/初始球数 × (1 − 0.7·融化度)
- 2–3 个球。
- 融化：每秒 +1/90；速度 < 1 m/s 时 ×1.5（停着不动也有代价）。
- 垂直冲击 `aLocal.y > 25 m/s²`（跳台落地、猛撞减速带）→ 最上面一球掉落（刚体碎片）。
- 翻车：掉 1 球。
- 视觉：甜筒 + 彩色球，随融化缩小、下垂，底下有滴落粒子。

完整度为 0（汤洒光、盒子全掉、球全掉）的订单仍可交付，但小费为 0，顾客说"我的外卖呢？？"。

## 6. 订单与特殊要求

- 同时存在的订单数 = `min(玩家数 + 2, 6)`。某单被取走/完成/过期后 3 s 补一单。
- 订单字段：`id, restaurantId, customerId, food, size(披萨盒数/冰淇淋球数), request, createdAt, timeLimit, status(waiting|carrying|delivered|expired), carrierId`。
- 待取订单 45 s 没人取 → 过期消失（不扣钱，但卡片变灰闪一下）。
- 配送时限：`timeLimit = 距离(餐厅→顾客)/8 + 25` 秒（从取餐开始计时）。超时仍可交，小费打折。

**特殊要求（每单 40% 概率带一个，全部都要真的被检查）：**

| id | 顾客卡片文字 | 检查 | 结果 |
|---|---|---|---|
| `noHorn` | "不要按门铃，狗在睡觉 🐕" | 交货前在顾客 30 m 内按过喇叭 → 失败 | 失败时狗叫音效 + "汪汪汪！" |
| `gentle` | "轻拿轻放，奶奶在午睡" | 本单配送途中翻过车 → 失败 | |
| `backDoor` | "放后门，别走正门" | 交货圈在楼的另一侧（生成地图时每个顾客点预设前门/后门两个位置） | 走错门不能交 |
| `rush` | "饿死了！快点！！" | 时限 × 0.6 | 按时 +额外奖励 |

## 7. 小费与结算

```
base      = 10 + 距离 × 0.08 + 尺寸加成(披萨每多一盒 +4，冰淇淋每多一球 +3)
integrity = 该订单完整度 (0..1)
timeMult  = 按时: 1 + 0.5 × 剩余时间比例；超时: 0.5
reqBonus  = 有要求: 完成 +8（rush 完成 +15），失败 −8；无要求: 0
tip       = max(0, round(base × (0.3 + 0.7 × integrity) × timeMult + reqBonus))
integrity == 0 → tip = 0
```

- 交货瞬间顾客头顶冒气泡，按完整度：≥0.9 "五星好评！" · 0.6–0.9 "还行吧…" · 0.3–0.6 "汤怎么只剩一半？"（按食物换词）· <0.3 "这是什么鬼？？" · 0 "我的外卖呢？？"；同时弹出小费明细（`+¥23  完整度 72% · 提前 18s · 狗被吵醒 −8`）。
- **团队星级**：`[60, 110, 160] × 玩家数`，对应 1/2/3 星。
- **个人奖项**（结算页，从统计里挑最突出的 3–4 个）：
  - 🍲 洒汤王（洒汤最多）· 💥 翻车王（翻车次数）· 📯 喇叭狂魔（按喇叭次数）· 🛡️ 最稳车手（平均完整度最高）· 🛫 飞行员（最长滞空时间）· 💰 小费王
- 每名玩家统计：`deliveries, tips, crashes, soupSpilled, pizzasLost, scoopsLost, honks, maxAirTime, integritySum`。

## 9. 画面、镜头、HUD、音效（"名场面"靠这些）

- **美术**：low-poly 纯几何体，明快配色，Three.js，1 盏平行光带阴影（阴影相机跟着本地玩家），半球光补光。静态楼用 InstancedMesh 或合并几何体，保证笔记本 60 fps。
- **玩家**：摩托 + 骑手用简单几何拼，4 种玩家颜色（红/蓝/黄/绿）；头顶显示名字。
- **镜头**：身后 6 m、高 3 m 平滑跟随；随速度 FOV 60→72；翻车时震屏。镜头要能清楚看到车后的货在晃。
- **导航**：目标点有高高的光柱（餐厅=餐厅颜色，顾客=白色）；屏幕边缘有指向当前目标的箭头；右下角 2D 小地图（canvas，画道路、餐厅、顾客、所有玩家）。
- **HUD（简体中文）**：
  - 左上：剩余时间、团队小费 ¥、星级进度条
  - 右侧：订单卡片（餐厅 → 顾客、食物图标、特殊要求、剩余时间条、状态：待取 / 配送中·某某）
  - 底部中央：当前货物完整度条 + 货物状态（"汤 68%"、"披萨 3/4"、"冰淇淋 2/3 · 融化 40%"）
  - 飘字：溢出"哗啦！"、掉盒"披萨飞了！"、翻车"翻车啦！"
- **音效**：全部用 WebAudio 合成，不引入音频文件：引擎嗡嗡声（音高随速度）、喇叭、狗叫、泼水、碰撞、交货叮咚。`?nosfx` 关闭。

## 10. 技术架构

**Web 技术栈**：TypeScript + Vite + three + cannon-es；服务器 Node + `ws`，用 `tsx` 运行。

```
delivery-chaos/
  package.json  tsconfig.json  vite.config.ts  index.html
  src/
    shared/                # 纯 TS，不碰 DOM/three，前后端共用
      constants.ts         # 所有可调参数集中在这里
      rng.ts               # mulberry32
      map.ts               # generateCity(seed) → 道路/楼/餐厅/顾客/跳台/减速带 描述数据
      orders.ts            # 订单生成、特殊要求
      scoring.ts           # 小费公式、星级、奖项
      rules.ts             # GameRoom：玩家、订单池、计时、取餐/交货裁决（服务器 & 单机共用）
      protocol.ts          # 消息类型
    sim/
      cargo.ts             # 三种货物模型（纯逻辑）
      balance.ts           # 倾斜/平衡模型（纯逻辑）
    client/
      main.ts              # 入口、菜单、URL 参数
      game.ts              # 主循环（固定步长物理 60 Hz，渲染 rAF）
      world.ts             # 由 map 数据建 three 场景 + cannon 静态碰撞体
      bike.ts              # 本地摩托控制器
      cargoView.ts         # 货物视觉 + 碎片刚体
      remoteBike.ts        # 远端玩家（插值）
      camera.ts  input.ts  audio.ts  minimap.ts
      ui/ hud.ts menu.ts lobby.ts results.ts  (+ style.css)
      net/
        transport.ts       # 接口
        localTransport.ts  # 单机：在浏览器里跑 shared/rules.ts
        wsTransport.ts     # 联机
  server/
    index.ts               # 房间管理；每个房间一个 GameRoom；同时托管 dist 静态文件
  tests/                   # vitest 单元测试（shared/ 与 sim/）
```

**关键原则：单机和联机走同一条代码路径。** 单机 = `LocalTransport` 在浏览器里跑同一个 `GameRoom`。

### 10.1 权威划分（派对游戏，信任客户端）
- **客户端权威**：自己的摩托位置/姿态、自己货物的完整度、翻车。
- **服务器权威**：订单池、谁拿了哪单、计时、小费计算、统计、结算。
- 客户端发 `pickup/deliver` 请求，服务器校验（该单状态、玩家是否空手、玩家上报位置在圈内）后广播结果。

### 10.2 协议（JSON over WebSocket，路径 `/ws`）
客户端 → 服务器：
- `hello {name}` · `createRoom` · `joinRoom {code}` · `startGame`（仅房主）· `backToLobby`（仅房主）
- `state {t, p:[x,y,z], h:heading, l:lean, v:speed, crashed, cargo:{kind, a, b, c}}` —— 20 Hz
- `pickup {orderId}` · `deliver {orderId, integrity, crashedDuring, honkedNear}`
- `honk` · `debris {kind, p, v}` · `stat {key, delta}`（洒汤量、掉盒等）

服务器 → 客户端：
- `welcome {id}` · `room {code, hostId, phase:'lobby'|'playing'|'results', players:[{id,name,color}]}`
- `start {seed, duration, serverTime}` · `orders {list}`（有变化时）
- `snap {t, players:{id: state}}` —— 20 Hz 合批
- `event {type:'pickup'|'deliver'|'expire'|'honk'|'debris'|'crash', ...}`
- `results {teamTips, stars, players:[...统计], awards:[...]}` · `error {msg}`

- 房间码：4 位大写字母（去掉易混的 I/O）。最多 4 人。房主掉线 → 下一个人当房主。
- 远端玩家渲染在 **100 ms 前** 的时间点做插值；远端的货物用 `cargo` 概要画出来（看得到队友的披萨塔在晃）。
- `debris`/`honk`/`crash` 事件广播，其他人也能看到队友的披萨飞出去、听到喇叭。

### 10.3 运行方式
- `npm run dev`：Vite（5173）+ 服务器（8080），Vite 把 `/ws` 代理到 8080。
- `npm run build && npm start`：单端口（`PORT`，默认 8080）同时托管静态文件和 WebSocket —— 方便丢到任何一台机器或隧道上和朋友玩。
- `npm test`：vitest。`npm run typecheck`：tsc --noEmit。

## 11. 验收标准（PM 会逐条检查）

**阶段 A（单机完整循环）**
1. `npm install && npm run typecheck && npm test && npm run build` 全部通过，无报错。
2. `?solo&seed=1&autostart` 进入游戏，能看到城市、自己的摩托、订单卡、小地图、计时器在走。
3. 骑车：能加速、转弯、刹车、甩尾、上跳台飞起来、撞墙；低速有明显晃动；乱开会翻车，翻车后能恢复。
4. 三种食物都能取餐 → 配送 → 交货，完整度变化可见，小费明细弹出正确。
5. 四种特殊要求都能被检查到。
6. 时间到 → 结算页（星级 + 奖项），"再来一局"可用。
7. 无头 Chromium 中无 console error；笔记本上稳定 60 fps（`?debug` 看）。

**阶段 B（联机）**
8. 两个浏览器：一个建房、一个用房间码加入，房主开始，双方看到同一张地图和同一批订单。
9. 能看到对方的摩托平滑移动（无明显抖动/瞬移），看得到对方的货在晃、披萨飞出、听到喇叭。
10. 一方取走的订单另一方不能再取；小费汇总到同一个团队池；结算页双方一致。
11. 一方断线不会让服务器或另一方崩溃。
